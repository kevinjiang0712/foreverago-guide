# 从母模板建立独立新站

```text
请使用当前母模板，为【游戏名称】建立一个独立站。
目标目录：【新的绝对路径】。目标语言：【语言清单及默认语言】。
主题方向：【已有预设名称，或希望调整的颜色/字体】。
我提供的真实资料与素材：【在这里粘贴】。

先阅读 README、AGENTS.md、docs/usage/start-a-site.md、
docs/usage/template-fields.md、docs/usage/change-theme.md。
确认目标目录不存在或为空，再运行项目的 create:site 命令；
复制后在新项目自己的目录工作，不覆盖现有站点，不携带母模板 Git 历史。

只替换 config、content、public/media。
- config/site.json：站点身份、真实域名/官方链接、语言与 SEO 默认项；
- config/categories.json：本站分类和对应入口；
- config/theme.json：主题、全局颜色与字体来源；
- content：公共字典、首页、MDX、实体记录、素材登记和翻译；
- public/media：本站真实素材。

严格复用已有12种模板的布局、组件和交互；不改 src/scripts/public/ui，
不建立跨站公共包，也不为换游戏重新生成一套前端。
有个别确实需要定制的模块，先给出具体差异和涉及页面，
确认它是否已经属于我的任务范围后再在本站单独实现。

所有示例游戏名、示例文案、实体关系和素材必须明确替换或列为待补。
没有来源支持的事实保持未知；不要编造游戏内容、官方网址、作者或更新日期。
预览阶段保持示例/preview 的 noindex 边界；不要把示例记录改为非示例来绕过检查。
只有真实资料替换完成并通过生产规则后，才能切换正式模式。

安装依赖，运行内容检查、类型检查、构建与 verify:site。
逐一处理实际错误，不关闭校验。提供本地预览，
并列出待补真实资料、当前页面网址、配置/内容变化和验证结果。
新站应有自己的本地 Git 记录。未经我明确要求，不远程建仓、不推送、不部署。
```

创建命令的 sample 是模板自带的演示集合，用于得到可预览骨架；它不是游戏事实来源。
