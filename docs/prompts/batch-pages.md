# 批量编写内页

先准备以下输入，再把提示词交给 AI。缺少真实来源时，应输出待补资料清单，不把示例资料发布成攻略。

## 输入

1. 当前项目目录、config/site.json 与 config/categories.json 摘要。
2. 目标关键词清单，包含每个关键词的目标语言和想解决的问题。
3. docs/usage/template-fields.md 对应模板字段及同模板的完整现有示例。
4. 来源资料：原始链接、文本、可确认事实、适用游戏版本、存在冲突的信息。
5. 已有文章 ID、记录 ID、素材 ID、分类 ID，避免创建重复实体。
6. 已提供的真实图片及授权用途；缺图时说明需要哪种图槽。

## 提示词

```text
请根据我提供的关键词与来源资料，为当前站批量编写内页。
先阅读 README、AGENTS.md、docs/usage/write-content.md、
docs/usage/template-fields.md，并检查当前项目实际 schema 和同模板示例。

逐一核对完整关键词清单，记录每个词对应的新页面、已有页面或不适用原因。
不要遗漏关键词；同义词可以归入同一页面，但必须列出映射。

仅修改 content、必要的 config/categories.json 与对应分类翻译，
以及已有或我明确提供的 public/media 素材。不要更改 src、scripts、组件布局或校验器。
使用已有模板的固定楼层；MDX 正文只填写该模板规定的正文槽。

为每页提供完整 frontmatter、正文及必要 JSON records。
稳定 ID 使用小写英文连字符；引用已有实体时复用原 ID，不用展示标题当引用。
保留 locale、category、template、status、verification、demo 等字段，
严格遵循当前模板必需字段。wiki-page 必须填写 guide 固定字段，
guide.table 同时登记在 records 中。其他模板按自己的 schema 填写。

正文不得出现 H1、import/export、任意 JavaScript 表达式、事件回调或脚本。
只使用项目允许的 MDX 组件：ContentLink、Media、DataTable、Notice、Steps，
组件参数按实际文档填写。站内链接使用内容 ID 和真实分类关系，不写 href="#"。
所有引用记录与素材必须存在于对应语言或登记表，不能生成坏引用。

来源不能证明的数值使用该字段允许的 null；叙述中明确未确认。
不要用 0 代表未知，不推算未公开实体数量，不虚构作者、发布日期、
游戏版本、官方链接、下载地址或来源。确认等级必须有相应证据。
示例数据保持 demo=true；新真实文章先保留 draft，由实际资料完整度决定后续发布状态。

翻译保留实体和内容 ID，同组文章可以使用不同 slug。
没有正文翻译的语言不要创建空页面，不要用英文文章假装完成翻译。

生成后运行 npm run check:content。报告每个新增/修改文件的路径、
对应关键词、实际网址、使用来源、未确认项和素材需求。
校验失败应修正内容本身，不修改校验规则；通过后运行对应构建检查。
只报告真实执行结果，不自动部署或推送远程。

下面是我的输入：
【配置摘要】
【完整关键词清单】
【模板字段与现有 IDs】
【来源资料及素材】
```

输出必须包含实际文件，不只给出页面提纲。缺少关键来源导致无法完成的页面应逐项注明，不生成看起来完整的虚构攻略。
