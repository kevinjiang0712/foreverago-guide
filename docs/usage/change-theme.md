# 适配游戏视觉

所有新站使用第一套 **Onimusha** 作为基础，保留日间和夜间模式。`preset` 固定为 `onimusha`；它是模板基础的名字，不限制最终网站必须采用鬼武者配色。

所有页面的 Hero 固定使用配置合并后的夜间令牌（包括文字、按钮、背景、遮罩与纹理）；日夜切换只影响其他区域。Hero 底图保持静止，不跟随鼠标或滚动位移，标题入场和按钮交互保留。

## 每个游戏只配置自己的视觉

| 要适配的元素 | 修改位置 | 全局规则 |
|---|---|---|
| 主色、底色、文字、边框与状态色 | `config/theme.json` 的 `day` / `night` | 同一令牌同时提供两种模式；文字与按钮填充分开定义 |
| 标题字体、正文字体、字重与字距 | `common`，本地字体在 `fonts` 登记 | 检查各语言字形、实际字重、长标题与加载情况 |
| 圆角、边框样式、阴影、颗粒与遮罩 | 现有主题令牌 | 字体与形状在明暗模式保持一致，遮罩按实际图片检查 |
| 既有动效的缓动与移动幅度 | 现有主题令牌 | 沿用固定动作与时长规则，遵守减少动效设置 |
| Logo、背景、人物、场景与内容图标 | `public/media/` + `content/assets.json`，在配置或内容中引用素材 ID | 按固定图槽尺寸准备素材；不改公共操作图标的含义 |

字号层级、行高、间距、断点、页面楼层和交互由框架统一维护。不要为了换游戏单独缩小正文或改写组件。

## 从游戏素材到配置

1. 收集官方页面、Logo、宣传图和游戏截图，记录来源。先判断主要底色、强调色、标题字形、边框形状与装饰特征；证据不足的项保留基础值。
2. 把这些特征映射到现有令牌。只覆盖确实不同的值，其他值继承标准主题，不复制整套 CSS。
3. 在当前独立站的 `config/theme.json` 填写覆盖；素材通过内容层替换。完整字段见 [配置说明](configuration.md#基于标准主题适配游戏视觉)。
4. 执行 `npm run prepare:theme`，修正具体的对比度、字体或配对错误；再运行内容检查与构建。
5. 在浏览器检查明暗模式、手机与电脑、长标题、图片上的文字、导航和按钮状态。配置校验不替代实际视觉检查。

示例 A 使用 Onimusha 默认值，示例 B 使用同一基础，通过少量配置改成蓝色强调色与较大圆角。新站不需要新增 preset，也不需要维护其他游戏站的主题代码。

## 可直接交给 AI 的要求

> 请基于这些官方素材【链接或文件】提取这个游戏的视觉特征，并记录来源。以当前 Onimusha 基础为起点，把配色、字体、形状、装饰映射到 config/theme.json 的现有令牌；图片通过内容与素材配置替换。只覆盖必要值，不新增 preset，不在组件里硬编码游戏颜色。保留模板字号层级、布局、楼层、交互和动效规则，兼顾明暗模式及各语言字形。无法确认的特征保留默认值。完成主题校验、构建和手机/电脑浏览器检查，说明修改了哪些全局规则。

母模板中的另外五套主题已归档，仅供提取视觉思路，不参与新站复制和持续验收。每个游戏站仍是独立副本，母模板后续变化不会自动影响已建站点。
