# 多语言与 SEO

你填写真实配置和内容，框架从同一索引生成页面标题、描述、canonical、多语言对应关系、结构化数据和 sitemap。

## 增加语言

1. 在 `config/site.json` 的 locales 中启用语言，defaultLocale 必须在其中。
2. 新建完整 `content/locales/<locale>.json`：站点名、分类文案、官方链接标签、页脚、按钮与无障碍文案都必须齐全。
3. 新建 `content/<locale>/home.json`。
4. 为需要翻译的文章新建该语言 MDX，以及页面依赖的同语言 records。
5. 给素材补该语言 alt。

配置只声明实际支持的语言，不应先挂出一批没有完成公共内容的语言入口。

## 对应关系如何建立

相同内容在不同语言中保持相同 id。文件的语言目录必须与 locale 字段一致；标题和文章 slug 可以不同。

默认语言使用根路径；其他语言使用语言前缀。分类 slug 来自公共分类配置，文章 slug 来自该语言文章。

没有翻译的文章不会回退显示英文来冒充翻译。语言切换会说明当前页面尚未翻译，并提供对应语言首页入口。不存在的语言或文章返回实际 404。

## 页面 SEO 填什么

- 每页填写独立 title 和 description。
- 全站 seo.titleTemplate 同时包含 `{title}` 和 `{siteName}`。
- 页面可在 seo 中覆盖 title、description、image、noindex。
- 分享图按页面显式图、页面 hero、全站图依次查找；显式 `image:null` 取消回退，没有真实图片时省略。
- 作者、发布日期、更新时间和版本只在真实已知时填写。不能把构建时间写成内容更新时间。

框架只为适用页面生成对应结构化数据；缺少作者等条件时不会捏造事实以补齐 Article。结构化数据通过不等于搜索引擎会展示富结果。

## 哪些页面可索引

演示模式与 preview 环境强制禁止索引。正式模式下还要满足发布状态、非示例及 noindex 配置等内容规则。

sitemap 只包含实际可索引页面。hreflang 只关联实际存在且可索引的翻译；如果默认语言有可索引对应页，才提供 x-default。缺翻译不会生成不存在的链接。

已发布但 noindex 的页面仍可以作为站内资料入口；它不应进入 sitemap 或其他页面的 SEO 多语言对应集合。

## 修改网址或删除文章

修改 slug 后，站内通过 ID 生成的链接会自动更新。需要保留旧网址时，在 site.redirects 配置明确的旧路径、目标内容 ID、语言和 permanent；不要手写第二篇重复文章。

删除文章并清理引用后，没有重定向的旧网址应返回 404。仅从导航隐藏文章不等于删除页面。

## 验证边界

`check:content` 检查格式和引用，`build` 检查能否生成页面，实际浏览器检查 HTML lang、标题、语言切换与 404；还应查看构建服务的 robots.txt、sitemap.xml 和 canonical/hreflang。

本地生成正确不代表已部署，更不代表已提交或已收录。未获明确授权不要自动推送、部署或提交搜索引擎。
