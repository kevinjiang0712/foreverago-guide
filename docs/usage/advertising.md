# 广告接入与布局

这是公共模板的广告契约；game-site-package 引用本文件，不维护另一套点位表。广告收益需要上线后的平台报表验证，本地验收只证明接入和布局行为。

## 默认点位

- 宽屏：正文第一完整章节后的 Native、左160×300、右160×600；双侧仅使用原版心外余量，间距24px、屏幕边缘至少16px。正文和目录宽度不受广告开关影响。
- 窄桌面：双侧空间不足则不请求、不展示，保留正文 Native，不自动补广告。
- 手机：最多正文 Native一组、后段300×250、可关闭顶部320×50；窄于368px时关闭按钮另占28px，避免覆盖广告创意。短文减少位置；正文广告之间至少1.5个视口的内容距离起测。320px窄屏如果正文容不下300px则不加载矩形广告，禁止缩放创意。
- 首页 Native在精选入口后；列表在第一组6条完整结果后，矩形在第二组之后；表格内部不插广告。地图和探索器在完整内容模块后插入，操作页面不显示手机悬浮广告。
- 关于、联系、政策、404页面不展示或请求广告。

## 配置

独立建站包使用可选 `site-spec/ads.json`，生成器验证后写入受保护的 `config/ads.json`；未提供时禁用。重新生成会保留输入配置，不手改生成文件。

`mode`：`disabled`、`placeholder`、`adsterra`。占位模式不请求广告平台。正式模式要求 `adsterra.allowedHosts` 为目标站实际主机名，并填写该站后台得到的 `units`：`native`、`left`、`right`、`inline`、`anchor`；未获批的单元可省略，缺单元不填占位代码。

每个Banner配置包含 `key`、`scriptUrl`；固定尺寸由点位决定，不重复填写。Native包含 `containerId`、`scriptUrl`。URL和ID必须来自目标站Get Code，不猜域名、不复用其他站代码。同页Banner key不能重复。Native先使用后台一列两卡起测，实际高度与收益另验收。

## 加载与路由

固定尺寸预留空间；Native保留初始高度并适应实际创意。正文广告提前一屏进入加载范围；隐藏的设备位置不请求。广告脚本直接插入页面内对应容器，不再包裹外层iframe；广告平台自身生成的创意iframe保留。各Banner按顺序设置atOptions并加载，脚本load/error后释放队列，避免串用key和尺寸；已开始请求的脚本卸载后仍等待load/error再释放，未开始的任务直接跳过。Native使用独立队列；切页后先等待旧脚本完成，再为新容器设置后台ID，防止旧响应写入新页面。固定广告挂在独立的文档节点，避免Next动态路由重建页面外壳时销毁广告；政策页仍立即清空。请求未返回时继续等待，明确脚本错误才有限重试，不用超时删除晚到广告，不进行定时刷新。

关闭侧栏或顶部条后本次会话保持关闭。固定侧栏在内容页切换时保留；真实页面变化按页面生命周期重新建立内容位；组件普通更新不重复请求。脚本完成、检测到创意节点、计费曝光与收益分别记录，不能互相替代。

## 验收

宽屏1920/1680、窄桌面1440/1280、手机390/320、短视口；涵盖首页、目录、普通攻略、结构化详情、工具、政策、404。验证正文几何、章节完整性、移动广告间距、关闭与切页、晚到创意、失败重试、隐藏位置零请求，以及生成/再生成后的配置保留。真实填充和收入需要获准上线环境及平台数据，不通过点击广告测试。
